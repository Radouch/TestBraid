# PoC-B publication controls and anonymous learner acceptance

**Status:** Implemented in draft PR #28. Automated CI must pass and real Apache/HTTPS acceptance remains pending.

## Author workflow

1. Sign in to the **Author area**. In **Existing tests**, select the lesson/group if desired.
2. Create or open a draft, use **Edit questions** to add all answers, correct-answer keys and any images/videos, then **Save questions**. The author-only **Preview / Try test** works before publication and does not expose the test or media to anonymous users.
3. Return to **Existing tests** and click **Publish** beside that test. The browser asks for explicit confirmation that the test and referenced media will be anonymously accessible. The backend revalidates the persisted test, media metadata and publishing invariants. If the test is incomplete, the application reports why publication failed; it does not change the status.
4. After successful publication the catalog displays **Published**, **Open public test**, **Copy link** and **Unpublish**. The public link is generated by Vue Router and thus respects the application deployment base path. A clipboard-denying browser shows a selectable read-only link instead of a false success message.
5. Share the copied URL: `/tests/<test-uuid>` under the deployed site. Anonymous learners can load test JSON and Apache static media and assess themselves, but no account or stored attempts are involved.
6. **Unpublish** requires another confirmation. The backend removes public test availability and reconciles public media copies, retaining a shared media file if referenced by another published test. The private original test and media stay available for further editing and future re-publication.

## Security and functional constraints

- Author API: `POST /api/admin/tests/{id}/publish` and `POST /api/admin/tests/{id}/unpublish` require an authenticated author and a valid session CSRF header. Frontend status is **never** considered authoritative; the server decides publication success.
- Public API: `GET /api/public/tests/{id}` returns HTTP 404 for unknown/unpublished tests. Public `/tests/{id}` does not send session cookies. The published JSON contains the correct-answer key because scoring is entirely local in the learner's browser.
- The public URL is not a secret or a proof of authorization. If the media/test contains confidential information, do **not** publish it. Browsers or recipients may retain already downloaded copies after withdrawal.
- The server publishes independent static media copies; changes in test status and media files are not one atomic filesystem transaction. Publication privacy/revocation design follow-up: Issue #16.
- Publishing controls are intentionally located in the **catalog**, not inside the question editor, to avoid publishing unsaved changes. Only the latest **saved** draft is submitted to the publication backend.
- The first increment deliberately leaves rich UI redesign and improved editor ergonomics as later work. The publish/share controls are functional, not a final style specification.

## Automated evidence

The PHP `test:publication-http` suite creates disposable private tests and uploads and tests: public draft 404, failed publish 422 for incomplete tests, successful publication, status conflict, static media, shared media, final-reference withdrawal, and anonymous access without sending a cookie. Newly added assertions check that public JSON contains the author-selected correct-answer IDs and media links; after withdrawal anonymous access returns HTTP 404. The Vue job typechecks/builds the catalog and its new action component and runs the existing question/scoring regression tests.

## Real-host acceptance (required before merge)

Back up server-owned `testbraid-backend/storage/` and `www/media/` if using any valuable data. Use **only disposable, non-sensitive media** for testing.

1. On the current host, build `feature/poc-b-publication-ui` and merge-upload only the staged `deployment-package/www/` files; **do not delete** preexisting public `www/media/` contents or private `config/`, `storage/`, `vendor/`. The PHP backend has not changed in this PR.
2. Sign in and make a draft with a complete single-choice and matching question; add an image and MP4 if available. Save and preview. Confirm the **Publish** confirmation and completed status switch.
3. Use **Copy link**, open the resulting URL in an entirely anonymous/incognito window, and verify test content, image/video playback and seeking. Answer questions incorrectly and correctly, check score and correct-answer feedback, and use **Try again**.
4. Unpublish via catalog. Verify public URL displays unavailable and `/api/public/tests/{id}` returns **HTTP 404**; return to author UI to confirm the test is a private draft and still editable.
5. Try publishing an **incomplete** disposable draft. Expect a clear explanation and no public test or asset exposure.
6. Optional shared-media regression: publish two disposable tests that reference the same media; withdraw one and verify the other still serves it. Withdraw both and verify public copies are removed without deleting private originals.

**Do not** claim real-host anonymous learner acceptance until these steps have been reported by the owner. Once passed, close Issue #21 and the remaining publish/share scope in Issue #20, merge PR #28 to `main`, and resume discussion of the question-editor UI.
